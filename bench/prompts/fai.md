Browser tools: use the FAI Browser MCP tools of server fai_browser (fai_browser_open, fai_browser_act, fai_browser_observe, ...; a host may name them mcp__fai_browser__fai_browser_open). They are tools, not MCP resources: if they are not in your direct tool list they are deferred, so find them in your tool search or ALL_TOOLS by the name fai_browser_open; never decide the browser is unavailable without that. The user has already opened {{START}} in their browser and will approve your tab request. Call fai_browser_open with origins ["{{ORIGIN}}"], a short reason and task set to the question; it returns the page digest and the offered actions with a revision.
Answer from page.digest when it answers the question. Otherwise call fai_browser_act with one actions[].id and that revision; each act returns the next page and actions. Give the act that should land on the final page an expectation that identifies it ({"urlIncludes": "<its path>"}, plus "textAbsent": "Loading" for content that loads late; never urlEquals, urlMatches or a menu word). fai_browser_observe with focus re-ranks a long page; digestChars reads more.
Follow next.kind literally; never repeat an identical call, call fai_browser_wait only on state "running", and do not call fai_browser_release at the end.
