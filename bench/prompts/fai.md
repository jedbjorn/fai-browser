Browser tools: use the FAI Browser MCP tools of server fai_browser (fai_browser_run, fai_browser_act, ...; a host may name them mcp__fai_browser__fai_browser_run). They are tools, not MCP resources: if they are not in your direct tool list they are deferred, so find them in your tool search or ALL_TOOLS by the name fai_browser_run; never decide the browser is unavailable without that. The user has already opened {{START}} in their browser and will approve your tab request. Make one fai_browser_run call with origins ["{{ORIGIN}}"], a short reason, an imperative instruction that names every page or link to visit in order and where to stop, an expectation that identifies the final page ({"urlIncludes": "<its path>"}, plus "textAbsent": "Loading" for content that loads late; never urlEquals, urlMatches or a menu word), answerQuestion set to the question, and maxActions about twice the clicks (at least 4).
Keep a task whose pages are all reachable by named links (for example About, then Docs) in that one run even when it joins facts from both pages: the trail carries the earlier page. Use several hops only when one run cannot do the task: which item or page to open depends on a value read first (pagination, "find X"), or it needs more than 3 clicks; never for one page. Then send them as steps in one fai_browser_run (steps: [{instruction, expectation, answerQuestion}, ...] instead of instruction; {{answer:1}} in a later step inserts step 1's answer: use it only when step 1's answerQuestion asks one name, number or URL); each step is verified and stepResults has each step's answer. When verdict.answer is set, your ANSWER is verdict.answer.text copied as is (it is already the value; with exact false, take only the requested part of that line); otherwise from page.digest and trail (answer.candidates are guesses; lists, Nth items and late-loaded text need the digest).
Follow next.kind literally: answer/answer_from_digest/confirm_page = reply without another call; choose = fai_browser_act with an option id and decide.revision; rerun/split = fai_browser_run with verdict.suggested and the same requestId; never repeat an identical call, call fai_browser_wait only on state "running", and do not call fai_browser_stop.
